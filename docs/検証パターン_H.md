# 検証パターン_H

**自作スクリプトを実機で検証するための素材**を、AviUtl2 の中だけで作るカスタムオブジェクトです。
階調・色相・肌色・アルファの輪郭など、検証に使うテストパターン 9 種類を、外部の画像を用意せずに出せます。
映像制作用の効果ではありません。

- `Script/検証パターン_H.obj2`（v1.01）

ふだんは検証プロジェクトの生成器（`AI/tools/make_debug_project.py`）がこのオブジェクトを置いて設定を書き込むので、
手で置くのは単発で確かめるときだけです。検証の手順は `.claude/rules/au2-verification.md` にあります。

## インストール

1. `Script\検証パターン_H.obj2` を配置する
2. AviUtl2 を再起動する

検証用のクリーン環境（`AI/devenv/`）にも、`au2 develop` で同じものが配置されます。

## 使い方

1. オブジェクトの追加メニューで、ラベル **HexScript** の中にある「検証パターン_H」（カスタムオブジェクト）を置く
2. **パターン** を選ぶ
3. **幅 / 高さ** で素材の大きさを決める（初期値は 1920 × 1080）
4. その下に、確かめたい効果を追加する

時間では変化しません（どのフレームも同じ絵）。

## パターンと向いている検証

**素材選びは検証の一部です。** 効果が触る性質を素材が持っていないと、効果が壊れていても絵が変わらず、判定が空振りします。

| パターン | 絵 | 向いている検証 | 向かない検証 |
|---|---|---|---|
| グレー階調 | 左の黒から右の白への横グラデーション | 明るさ・コントラスト・ガンマなど輝度への操作（リフト・ガンマ・ゲイン、LUT、レンジ警告） | 彩度・色相への操作、チャンネルの入れ替え（R=G=B なので変化が出ない） |
| 虹色 | 左から右へ色相が 0 → 360 度。彩度・明度は最大で一定 | 色相ごとに効く補正（HSL 選択補正） | 彩度を上げる操作（もともと最大） |
| HSLチャート | 横 12 色相 × 縦 25 行（彩度 5 段 × 明度 5 段）のタイル | 色相・彩度・明度の選択補正、バイブランス、彩度を見る警告表示 | - |
| 肌色帯 | 横縞 8 本。上の 6 本が肌色（上ほど暗い → 下ほど明るい）、下の 2 本が低彩度の参照色。どの帯も左端が無彩色で、右へ行くほど帯の彩度になる | バイブランスの肌色保護（肌色だけ効きが弱まるか、低彩度側に効きすぎないか） | - |
| 飽和ランプ | 黒 → 白の横グラデーション。左 1/7 は真っ黒、右 1/7 は真っ白に張り付く | 黒つぶれ・白飛びの検出（レンジ警告） | 彩度・色相への操作 |
| 硬マット | 白いロの字の枠（外側と中央の穴は透明）。縁にアンチエイリアスが無い | 収縮・膨張・輪郭の形（マット調整）。外向きの辺と内向きの辺の両方を見られる | RGB への操作（RGB は白一色） |
| 軟マット | 白い円。中心は不透明で、外へ向かってアルファだけが 1 → 0 に下がる。RGB は白一色 | アルファへの操作（マット調整の黒レベル・白レベル、エッジぼかし） | RGB への操作 |
| グリーンバック | 緑（`00ff00`）の背景に肌色寄りの円。円の縁は緑と混ざる。**全面が不透明** | スピル除去・キーイング | 半透明の部分を前提にする検証（アルファは全面 1） |
| 微グラデーション | 50% の灰色を中心に、明度差の分だけ明るさが変わるごく緩い横グラデーション | バンディング（階調の段）の確認（LUT） | - |

検証の台帳（`AI/verification/verification_checklist.md`）では、グレー階調を LGG・LUT・RNG、虹色を HSL、
HSLチャートを HSL・VIB・RNG、肌色帯を VIB、飽和ランプを RNG、硬マットと軟マットを MAT、グリーンバックを SPL・MAT、
微グラデーションを LUT の節で使う想定です（スクリプト冒頭の対応表）。

## パラメータ

| 項目 | 範囲 / 選択肢 | 初期値 | 説明 |
|---|---|---|---|
| 幅 | 16 ~ 4000 | 1920 | 素材の幅（px） |
| 高さ | 16 ~ 4000 | 1080 | 素材の高さ（px） |
| パターン | グレー階調 / 虹色 / HSLチャート / 肌色帯 / 飽和ランプ / 硬マット / 軟マット / グリーンバック / 微グラデーション | グレー階調 | 出すテストパターン（上の表） |
| 段数(0で連続) | 0 ~ 64 | 0 | 階調を何段に分けるか。0 は連続（段なし）。1 は一色（下の表） |
| 明度差 | 0.1 ~ 20.0 | 2.0 | 微グラデーションの、左端と右端の明るさの差（%）。**パターンが 微グラデーション 以外のときは隠れる** |
| 縁の柔らかさ | 0 ~ 100 | 30 | 円の縁でぼける幅（%） |
| 余白 | 0 ~ 45 | 15 | 図形の外側に空ける余白（%） |

**補助の 4 項目（段数・明度差・縁の柔らかさ・余白）は、パターンによって効くものが違います。**
明度差以外は、効かないパターンでも隠れません。

| 項目 | 効くパターン | 効き方 |
|---|---|---|
| 段数(0で連続) | グレー階調 / 虹色 / 飽和ランプ | 階調（虹色では色相）を指定した段数に分ける。グレー階調と飽和ランプは両端が 0 と 1 になり、段数 1 では 50% の灰色一色。虹色は色相を 0, 1/n, …, (n−1)/n の n 色に分けるので、両端が同じ赤にならない（4 段なら 赤 / 黄緑 / シアン / 紫）。段数 1 では赤一色 |
| 明度差 | 微グラデーション | 50% ± 明度差/2 %。2.0 なら 49% ~ 51%（8 bit で出力するとおよそ 5 段） |
| 縁の柔らかさ | 軟マット / グリーンバック | 円の外周から内側へ、この幅でアルファ（グリーンバックでは色）が変わる。短い辺の半分を 100% とする。0 で縁が硬くなる |
| 余白 | 硬マット / 軟マット / グリーンバック | 硬マットは枠の外側の余白（幅・高さそれぞれに対する %。左右・上下で半分ずつ）。穴は外側の枠の半分の大きさ。軟マットとグリーンバックは円の半径が「短い辺の半分 × (100 − 余白)%」になる |

初期値（1920 × 1080・余白 15・縁の柔らかさ 30）では、硬マットは 1632 × 918 の枠に 816 × 459 の穴、
軟マットは半径 459 px の円で、中心から 297 px までが不透明です。

## 注意

- **アルファに輪郭があり、RGB にも模様がある素材はありません。** アルファに輪郭を持つのは硬マットと軟マットだけで、どちらも RGB は白一色です。
  RGB に模様のある素材はどれもアルファが全面 1 なので、エッジぼかしのように「アルファの輪郭の周りで RGB がどう変わるか」を見る検証には使えません
- 硬マット・軟マットは透明な部分を持ちます。透過のまま出力した画像を見るときは、シーンの背景色を敷くか、
  `AI/tools/composite_shots.py` で市松模様の上に合成してから見ます（白い素材を白い背景に置くと何も写っていないように見える）
- HSLチャートは名前に反して、内部では HSV（色相・彩度・明度）で色を作っています。彩度・明度はどちらも 20% ~ 100% の 5 段で、0 は含みません
- 硬マットの枠は縦横比に合わせて伸びます（正方形の枠にはなりません）。円は縦横比を補正しているので、どの大きさでも真円です
